# Tickets Module — Implementation Plan (misfit-bot)

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** A self-contained `tickets` Go plugin module — grouped tickets opened from an in-chat button panel, role+opener pings, templated embed with opener-avatar thumbnail and Claim/Close buttons, full conversation logging (text/images/videos/stickers/attachments incl. edits+deletes), and dashboard list/transcript/close integration.

**Architecture:** New Go plugin `modules/Go/tickets/` built to `tickets.so`. Cross-module contract via a small `modules.TicketProvider` interface in the core package; the dashboard consumes it by name through `Manager.Get("tickets")` and type-asserts, so the two modules never hard-depend on each other. Persistence = one JSON file per ticket under the module's `DataDir`, plus a lightweight `index.json` per guild. Groups are configured via one YAML textarea field (`groups_yaml`) rendered automatically by the dashboard's existing WebConfigurable pipeline.

**Tech Stack:** Go 1.26.4 · disgo v0.19.6 (`GuildPrivateThreadCreate`, `events.ComponentInteractionCreate`, embed builders) · yaml.v3 · existing `embed` helpers · existing dashboard render/ACL pipeline.

## 1. Goal & Non-Goals

**In scope**
- Groups (e.g. `staff`, `room-applications`) each with own settings + enable/disable switch; disabled group → greyed Open button on the panel.
- On open: ping configured roles + opener; post templated embed with `{user}`-style placeholders, opener avatar as thumbnail (top-right), Claim (greys when taken) + Close buttons.
- Full per-ticket conversation log: every message, images/stickers/videos/attachments, edits (overwrite+flag) and deletes (tombstone).
- Dashboard: open-tickets list, transcript viewer (media renders), close action. Small CSP touch-up.
- Primary UX = in-chat buttons; only optional owner conveniences as text/slash commands.

**Non-goals:** external DB, categories/SLAs/priorities beyond group config, forum auto-ticketing, message-history backfill.

## 2. Data model & storage

Persisted under `ctx.DataDir/tickets/<guildID>/`:

```go
// lives in modules/tickets_contract.go (shared with dashboard)
type Ticket struct {
    ID        string     `json:"id"` // "<group>-<seq>" e.g. "staff-0007", seq per guild+group
    Group     string     `json:"group"`
    GuildID   string     `json:"guild_id"`
    ChannelID string     `json:"channel_id"`
    MessageID string     `json:"message_id"`
    OpenerID  string     `json:"opener_id"`
    ClaimerID string     `json:"claimer_id"`
    ClaimedAt time.Time  `json:"claimed_at"`
    OpenedAt  time.Time  `json:"opened_at"`
    ClosedAt  time.Time  `json:"closed_at"`
    Status    string     `json:"status"` // "open" | "closed"
    Log       []LogEntry `json:"log"`
}

type LogEntry struct {
    MsgID       string    `json:"msg_id"`
    AuthorID    string    `json:"author_id"`
    AuthorName  string    `json:"author_name"`
    IsBot       bool      `json:"is_bot,omitempty"`
    Timestamp   time.Time `json:"ts"`
    Content     string    `json:"content"`
    Attachments []Media   `json:"attachments"`
    Stickers    []Media   `json:"stickers"`
    Edited      bool      `json:"edited"`
    Deleted     bool      `json:"deleted"`
}

type Media struct {
    URL         string `json:"url"`
    ProxyURL    string `json:"proxy_url,omitempty"`
    Kind        string `json:"kind"` // image | video | sticker | file
    ContentType string `json:"content_type,omitempty"`
    Filename    string `json:"filename,omitempty"`
    Size        int    `json:"size,omitempty"`
}

type TicketSummary struct { // dashboard list rows
    ID, Group, GuildID, OpenerID, ClaimerID, Status string
    OpenedAt time.Time
}

type GroupSummary struct{ Key, Label string; Enabled bool }
```

Layout:
```
tickets/<guildID>/<ticketID>.json   # full ticket + log (atomic write: tmp+rename)
tickets/<guildID>/index.json        # {"open":["staff-0007",...]} rebuilt from scan if missing
```
In-memory: `map[guildID]map[ticketID]*Ticket` guarded by `sync.RWMutex`; flush on every mutation. Closed tickets stay on disk until retention prunes them (default 30 days).

## 3. Configuration (WebConfigurable)

Schema returned by `WebConfigSchema()`:

| Key | Type | Scope | Notes |
|---|---|---|---|
| `groups_yaml` | textarea | global | The groups list (§4). Parsed + validated on every set. |
| `control_channel` | channel | guild | Where the staff panel lives. |
| `log_channel` | channel | guild | Optional closed-ticket summary target (empty = off). |
| `storage_retention_days` | number (min 0, max 3650) | global | 0 = keep forever. Default 30. |
| `allow_dashboard_close` | toggle | global | false [DEFAULT] → owner/elevated only. |

Groups YAML (validated: unique keys, parent_channel set when enabled):
```yaml
- key: staff
  label: "Staff"
  enabled: true
  parent_channel: "123..."
  ping_roles: ["111...", "222..."]
  embed_template: |
    {user} opened a **{group}** ticket in **{guild.name}**.
    > Please describe your issue.
  color: "0x5865F2"
  allow_claim: true
  allow_close: true
```

## 4. Lifecycle

**Open** (panel Open button `tickets:open:<group>`): create private thread via `CreateThread(parent, GuildPrivateThreadCreate{Name: "<label>-<username>-<seq>", Invitable: &false})`; send ping line (`<@&role…> <@opener>`) + templated embed (`Thumbnail: opener avatar 512px`, `Color: group color`, author = opener tag+avatar, timestamp); attach ActionRow [Claim=Primary, Close=Danger] respecting `allow_claim`/`allow_close`; persist ticket + index. Ephemeral confirm with thread link.

**Claim** (`tickets:claim:<id>`): requires `ManageMessages` (or later staff_role). First click sets claimer, edits message → Claim becomes Secondary+disabled+label `Claimed by <name>`; later clicks → ephemeral "already claimed".

**Close** (`tickets:close:<id>` OR dashboard POST — single `CloseTicket()` path): status/closedAt set, both buttons disabled, footer `Closed by <name>`, thread archived+locked, closure LogEntry appended, index updated, optional `log_channel` summary.

**Logging** (`OnLoad` registers `AddGuildMessageCreate/Update/Delete`): map ChannelID→Ticket; append entries (skip bot's own posts); update→overwrite content + `Edited=true`; delete→`Deleted=true` tombstone. Attachments classified by Content-Type prefix (`image/`,`video/`, else file); stickers via `StickerItems` (Lottie format 3 → use preview asset URL).

## 5. Dashboard integration

- Page route `case "tickets":` in `server.go route()` → `requireAuthed(handleTicketsPage)`; nav entry shown staff+. Query param `?guild=` reuses the settings-page guild-selector pattern; transcript at `/tickets/<guildID>/<ticketID>`.
- API routes in `api2.go routeAPI()` new `case "tickets":`: GET list (+groups), GET one, POST close. Close gated owner/elevated unless `allow_dashboard_close=true` (then elevated too). 404 when tickets module absent/ticket missing; 403 without permission.
- Templates: `tickets.html` (list w/ guild selector + Close buttons) and `transcript.html` (entries in order; text as Markdown-ish plain text, media grid; tombstones rendered struck-through; stickers via preview URL).
- CSP change (server.go:71): `img-src 'self' https://cdn.discordapp.com https://media.discordapp.net data:` + add `media-src 'self' https://cdn.discordapp.com https://media.discordapp.net;`.

## 9. Risks / tradeoffs / notes

- **Plugin ABI:** tickets must be rebuilt together with the host on updates — already handled by the updater's recursive plugin discovery (PR #16).
- **Log growth:** video attachments make JSON files big; acceptable at expected volume; retention default 30d mitigates. Revisit only if size becomes real.
- **Race surface:** store is mutex-guarded; `-race` in Task 4 covers it.
- **Ephemeral replies:** use `discord.MessageFlagsEphemeral` for errors so failures don't spam channels.
